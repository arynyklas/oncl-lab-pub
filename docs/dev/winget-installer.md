# Установщик для WinGet (`oncl-winget-setup`)

WinGet запускает установщик и доверяет его коду возврата. Закреплённый Velopack `Setup.exe` при переустановке принудительно завершает установленную программу, даже посреди подписи, а при невыполненных предварительных требованиях выходит с кодом 0, ничего не установив. Поэтому в ассет для WinGet кладётся небольшая программа `oncl-winget-setup`. Она несёт внутри неизменённый `Setup.exe` и сама решает, можно ли его запускать. Файл называется `openncalayer-<версия>-win-<x64|x86>-winget-setup.exe` и работает только на Windows 10 1809 и новее. Для вариантов Windows 7 такого установщика нет, у них остаются обычные.

Дальше эта программа называется обёрткой.

## Что делает обёртка

1. Отказывается работать с повышенными правами. Проверка идёт до любых записей, потому что установка делается в профиль пользователя.
2. Читает вложенный `Setup.exe` из собственного образа и проверяет его SHA-256, версию и архитектуру (`payload.rs`). Вложение лежит сразу после последней секции PE и перед таблицей сертификатов Authenticode; после таблицы данных быть не может.
3. Если программа уже запущена, просит её приостановиться через отдельный канал управления пользователя (`oncl_ipc::maintenance`; это не WSS и не native messaging). Решение принимается так же, как у встроенного модуля обновления (`Host::hold`): сначала задерживаются новые запросы, затем проверяются идущие операции, период QUIET и открытые окна. Удержание действует, пока жива связь по IPC, так что убитая обёртка не оставит программу занятой навсегда; кроме того, его ограничивает `MAX_LEASE`. Если программа занята дольше `--wait` (по умолчанию 180 с), обёртка завершается с кодом 4 и установку не трогает. Если запущена старая версия без канала управления, код 5. Принудительно обёртка ничего не завершает.
4. Распаковывает `Setup.exe` в закрытый каталог и запускает `Setup.exe --silent` без других ключей.
5. Коду возврата `Setup.exe` не верит. Установку подтверждают манифест по локатору Velopack, сама программа (`--version`) и запись HKCU Apps & Features (версия, расположение, деинсталлятор).
6. После подтверждённой установки снова запускает программу, если она работала до этого. При чистой установке окон не открывает.

Коды выхода:

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | прочий сбой |
| 2 | неверные аргументы |
| 3 | вложенный `Setup.exe` повреждён или отсутствует |
| 4 | программа занята |
| 5 | у запущенной программы нельзя спросить |
| 6 | `Setup.exe` завершился ошибкой |
| 7 | `Setup.exe` вышел, но нужная версия не установлена |
| 8 | повышенные права |
| 9 | не Windows |

Успехом считается только 0, поэтому `InstallerSuccessCodes` в манифесте WinGet расширять нельзя.

## Манифест приложения

В образе обёртки должен быть ресурс `RT_MANIFEST` с `requestedExecutionLevel level="asInvoker"` и GUID `supportedOS` для Windows Vista–11. Без него Windows по имени файла (`…-winget-setup.exe`, в нём есть «setup») принимает программу за старый установщик и до запуска показывает запрос UAC «Разрешить этому приложению от неизвестного издателя…». Без интерактивного сеанса запуск тогда падает с `ERROR_ELEVATION_REQUIRED` (740). Соглашаться на запрос бесполезно: права станут повышенными, и обёртка откажет с кодом 8. Манифест Velopack `Setup.exe` лежит во вложении и к самой обёртке не относится.

Манифест лежит в `crates/oncl-winget-setup/windows/oncl-winget-setup.manifest`. `build.rs` передаёт его компоновщику MSVC (`/MANIFEST:EMBED /MANIFESTINPUT /MANIFESTUAC:NO`), так что ни дополнительный пакет, ни `rc.exe` не нужны, и для x64 и x86 всё одинаково. Ресурс занимает отдельную секцию `.rsrc` перед `.reloc`. Вложение по-прежнему дописывается после последней секции и перед таблицей сертификатов, поэтому `payload::append/read` и порядок подписи (сначала `package winget-setup`, потом Authenticode всего файла) остаются прежними. `cargo xtask package winget-setup` отказывается собирать обёртку без манифеста `asInvoker` (`oncl_winget_setup::manifest`), а тесты `crates/oncl-winget-setup/tests/manifest.rs` читают ресурс из собранной обёртки и проверяют, что вложение находится.

## Порядок выпуска (release.yml)

1. Сборка обёртки (`--no-default-features`, без тестовой обвязки).
2. `vpk pack`.
3. Подпись Authenticode для `Setup.exe`, если настроен SignPath.
4. `cargo xtask package winget-setup` вкладывает уже подписанный `Setup.exe` в обёртку.
5. Подпись Authenticode самой обёртки отдельным запросом к SignPath (артефакт `signpath-unsigned-winget-setup-<вариант>`; в конфигурации артефакта SignPath должен быть разрешён `*-winget-setup.exe`).
6. Публикуются именно эти байты, их SHA-256 попадают в `SHA256SUMS` релиза.
7. По ним строится манифест WinGet (`cargo xtask winget manifest`, [`winget.md`](winget.md)).

Без SignPath обёртка публикуется неподписанной, в журнале остаётся notice.

## Как проверяется

`cargo test -p oncl-winget-setup --test maintenance` запускает настоящие процессы и настоящий IPC пользователя. Тесты проверяют, что идущая операция не прерывается и `Setup.exe` не стартует, что новые операции блокируются на время удержания, что убитая обёртка освобождает программу, что открытое окно и незакончившийся период QUIET дают «занято». Отдельно проверяется отказ, когда `Setup.exe` вышел с кодом 0 без установки или поставил не ту версию (манифест, запись ARP, программа, расположение, архитектура). Вместо Velopack `Setup.exe` тесты используют обвязку `oncl-winget-harness`: поддельный рабочий стол за настоящим `ActivityGate` и поддельный `Setup.exe`, который пишет в одноразовый каталог и одноразовый ключ HKCU `OpenNCALayer-test-*`. Настоящий `Setup.exe` пишет настоящую запись ARP, и перенаправить его в одноразовый корень нельзя.

Три теста с настоящим демоном помечены `#[ignore]` и требуют обвязку: `real_idle_daemon_is_held_for_setup_and_released`, `real_signing_in_flight_gets_busy_and_completes_correctly` и `a_killed_installer_releases_the_real_daemon` в `crates/openncalayer/tests/maintenance_e2e.rs`. Обвязка собирается командой `cargo build -p oncl-winget-setup --bin oncl-winget-harness`, тесты запускаются так: `cargo test -p openncalayer --features e2e-prompter --test maintenance_e2e -- --ignored`. Окно Slint (`any_window_open`) в настоящем демоне без экрана не проверяется. CI (`ci.yml`, задание `windows-package`) собирает обёртку без обвязки, запускает `cargo xtask package winget-setup` с проверкой PE и `cargo test -p oncl-winget-setup --test maintenance`.

## Шаг оператора: конфигурация артефакта SignPath

Секреты и серверные настройки SignPath в репозитории не хранятся. Перед первым релизом с установщиком для WinGet мейнтейнер один раз настраивает проект в SignPath. `release.yml` отправляет на подпись отдельным запросом артефакт `signpath-unsigned-winget-setup-<вариант>`: zip с одним файлом `openncalayer-<версия>-win-<x64|x86>-winget-setup.exe`. В конфигурацию артефакта (`artifact-configuration`; та же, что подписывает `signpath-unsigned-setup-*`, или отдельная, на которую указывает `SIGNPATH_SIGNING_POLICY_SLUG`) нужно добавить элемент `<pe-file path="*-winget-setup.exe">` с тем же шагом Authenticode. Пока его нет, SignPath отклонит запрос и задание `binaries` упадёт, неподписанный файл при этом не выйдет. Если секретов SignPath нет совсем, шаги подписи пропускаются и установщик публикуется неподписанным, с notice в журнале.

## Гонка: программа запустилась, пока готовился `Setup.exe`

Последняя проверка процессов (`last_look`, одна попытка без повторов) идёт после повторной сверки SHA-256 копии `Setup.exe`, непосредственно перед его запуском. Если при первой проверке программы не было, а теперь она есть, её удерживают обычным образом. Любой другой процесс установки, которого не спрашивали (ещё один `openncalayer.exe`, `Update.exe`, второй демон), отменяет запуск с кодом 4, потому что `Setup.exe` завершает все процессы под корнем установки (`nmhost.exe` не считается).

Остаётся окно в несколько секунд: от этой проверки до момента, когда `Setup.exe` (чтение своего образа, предварительные требования, проверки места и ОС) доходит до принудительной остановки процессов. Демон, запущенный ровно в это время (автозапуск при входе, ретранслятор расширения), не удержан и может быть остановлен. Закрыть окно можно только правкой `Setup.exe`, а закреплённый Velopack не меняется. Другой путь: метка «идёт обновление» (именованный mutex или файл в каталоге данных), которую обёртка ставит до первой проверки, а демон и ретранслятор учитывают при старте. Это поможет только версиям, которые знают о метке.

## Особые случаи

- Запущена старая версия без канала управления: код 5.
- Администратор при выключенном UAC получает код 8, так и задумано.
- Два установщика одновременно без демона: взаимной блокировки между ними нет, порядок определяет собственная блокировка `Setup.exe`.
- Страница, которая опрашивает NCALayer (`getActiveTokens`), продлевает период QUIET, поэтому код 4 при занятом браузере нормален.
- `winget install --interactive` запускает обёртку без `--silent`, и она выходит с кодом 2.
- Понижение версии обёртка не запрещает.
- Не учитываются: `oncl-server` без экрана, `oncl` и программы, встроившие SDK (они не входят в пакет для рабочего стола); сканирование токенов в окне «Инструменты», которое идёт мимо Engine (его покрывает признак открытого окна). Новые окна во время удержания не блокируются, их операции ждут в `begin`.
- Код 4 в манифесте WinGet не считается успехом (`InstallerSuccessCodes` не расширять).
- `Setup.exe`, не завершившийся за 15 минут, не останавливается: удержание снимается, временная копия остаётся.

## Что считается операцией (учёт в одном `ActivityGate`)

| Источник | Как учитывается |
|---|---|
| Запрос модуля от страницы по WSS и через мост (в том числе вызовы плагинов: это те же модули) | `session::dispatch` берёт `ActivityLease` на время обработки |
| Операции окна «Инструменты» (подпись, хеш, сведения) | `Engine::with_activity`: lease привязан к `OperationLease` и живёт, пока последний владелец операции (контекст, нативный рабочий поток, ответ) не отпустит её |
| Открытое окно (подтверждение, настройки, мастер TLS, плагины) | `DaemonHost::hold` запрашивает `window_open` уже после удержания |
| Встроенный модуль обновления, второй установщик | тот же `hold`, исключительный |

## Пределы `last_look` и запуск тестов

- Процессы, которые нельзя открыть (другой сеанс, защищённые), `last_look` пропускает. Охват тот же, что у принудительной остановки в самом `Setup.exe`. Отказ даёт только сбой снимка списка процессов.
- Тесты для других ОС (`tests/maintenance/main.rs`) запускаются только вручную, например в WSL: `cargo +1.99.1 test -p oncl-winget-setup --test maintenance`. Три теста с настоящим демоном, помеченные `#[ignore]`, требуют заранее собранной обвязки (`cargo build -p oncl-winget-setup --bin oncl-winget-harness`).
