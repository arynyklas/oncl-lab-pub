# Расширение браузера

Расширение перехватывает на странице `WebSocket` к `127.0.0.1`, `localhost` и `[::1]` на портах 13579–13679 и передаёт сообщения OpenNCALayer через native messaging. Браузер запускает небольшой relay `nmhost`, а relay запускает демон (`openncalayer run --allow-no-wss`), если тот ещё не работает. Сертификат и порт 13579 для этого не нужны. `wss` и установленный CA нужны только сайтам в браузерах без расширения.

Готовые файлы расширения лежат в [Releases](https://github.com/arynyklas/OpenNCALayer/releases): `openncalayer-chromium-<версия>.zip` и `openncalayer-firefox-<версия>.xpi`. `.xpi` обычного релиза (версия без суффикса, например `0.1.1`) подписан Mozilla, и Firefox ставит его насовсем, если при сборке релиза были ключи AMO. `.xpi` предварительной версии (`-alpha`, `-beta`, `-rc`) не подписан и ставится только временно. Расширение можно и собрать из исходников:

```sh
cargo build --release -p openncalayer -p oncl-nmhost
cargo xtask ext build   # → target/extension/
```

`ext build` кладёт в `target/extension/` распакованные расширения `chromium/` и `firefox/`, а рядом `openncalayer-chromium-<версия>.zip` и неподписанный `openncalayer-firefox-<версия>.xpi`.

Установка:
1. `openncalayer nm install` регистрирует хост native messaging `io.github.arynyklas.openncalayer`. Установщики и первый запуск установленной копии делают это сами (раздел [«Установка»](install.md#установка)). Команда:
   - копирует relay `nmhost` в `%LOCALAPPDATA%\OpenNCALayer\nmhost.exe` (Windows) или в каталог данных (macOS, Linux). По умолчанию берётся relay, лежащий рядом с `openncalayer`, другой путь задаётся ключом `--relay <файл>`;
   - пишет рядом `nmhost.json` с абсолютными путями к каталогу данных и к `openncalayer` (у AppImage это путь к самому файлу `.AppImage`);
   - пишет манифесты хоста. В macOS и Linux они пишутся для найденных браузеров (Chrome, Chromium, Edge, Brave, Yandex Browser, Firefox), в Windows всегда создаются `%LOCALAPPDATA%\OpenNCALayer\nm\{chromium,firefox}.json` и ключи `HKCU\Software\{Google\Chrome,Chromium,Microsoft\Edge,Mozilla}\NativeMessagingHosts\io.github.arynyklas.openncalayer`.

   Сертификаты команда не трогает. Проверить регистрацию можно командой `openncalayer nm status` (код 1, если чего-то не хватает), удалить командой `openncalayer nm uninstall` (каталог данных остаётся).
2. Chrome, Edge, Yandex Browser: откройте страницу расширений (`chrome://extensions`, `edge://extensions`), включите «Режим разработчика», нажмите «Загрузить распакованное расширение» и выберите каталог `target/extension/chromium` или распакованный `openncalayer-chromium-<версия>.zip`. Id расширения должен быть `cmdaoegbcpdhoamhgmibpgpnlojopcal`, расширение с другим id хост не принимает.
3. Firefox (115 и новее, в том числе ESR 115 — последний Firefox для Windows 7): скачайте `openncalayer-firefox-<версия>.xpi` обычного релиза из Releases и откройте его в Firefox: перетащите файл на окно браузера или выберите `about:addons` → значок шестерёнки → «Установить дополнение из файла…». Файл подписан Mozilla как unlisted-дополнение (в каталоге addons.mozilla.org его нет), поэтому дополнение остаётся после перезапуска Firefox. Подписанные версии обновляются сами: Firefox проверяет `https://arynyklas.github.io/OpenNCALayer/firefox/updates.json` и берёт новый подписанный `.xpi` из Releases. Firefox не установит `.xpi` предварительной версии, локальной сборки и релиза, вышедшего без ключей AMO. Для них остаётся временная установка: `about:debugging` → «Этот Firefox» → «Загрузить временное дополнение…» → `target/extension/firefox/manifest.json`; такое дополнение пропадает при перезапуске Firefox.
4. Перезагрузите открытые вкладки сайтов.

Что нужно знать:
- `nm install` определяет каталог данных так же, как `run`, с учётом `ONCL_DATA_DIR`. После переноса `openncalayer` или смены каталога данных повторите `nm install`.
- Повторный `nm install` заменяет relay переименованием, и копии relay, уже запущенные браузером, продолжают работать со старым файлом. Старые файлы `nmhost.old-*` удаляются при следующем `nm install`. В Windows `nm uninstall` не может удалить relay, пока его держит браузер (строка relay «занят запущенным процессом», код 1): закройте браузер и повторите команду. В macOS и Linux файл удаляется сразу.
- Демон, запущенный relay, работает до конца сеанса. Если TLS настроен и порт 13579 свободен, тот же демон обслуживает и `wss`. Иначе он пишет предупреждение в журнал и работает только для расширения, пока пользователь не остановит оригинал или не сохранит сертификат в мастере.
- Origin сайта, который передаётся модулям, при работе через расширение берётся у браузера, а не у страницы.
- Если хост не установлен или демон не запускается, расширение отдаёт странице её обычный `WebSocket`, то есть оригинальный NCALayer, если он запущен. Пока хост установлен, сайты обращаются к OpenNCALayer, даже если оригинал работает. Чтобы вернуться к оригиналу, выполните `nm uninstall` и перезапустите браузер (или завершите демон) либо отключите расширение. Сразу после `nm uninstall` браузер ещё работает через уже запущенные relay и демон.
- После отключения расширения открытые вкладки в Chromium и Firefox 128 и новее сами переходят на обычный `WebSocket`, но только для новых сокетов и `fetch`. В Firefox ESR 115 вкладки нужно перезагрузить (см. ниже). Сокет, который уже был открыт через расширение, на оригинал не переключается. В Firefox 128 и новее при следующем `send` страница получает `error` и `close` с кодом 1006 (следующей задачей, как это делает браузер, а не изнутри `send`), и запрос, ожидающий ответа, завершается ошибкой. Сокет, который только ждёт сообщений, ничего не получает и остаётся открытым, пока страница его не закроет или снова не обратится к NCALayer (новый сокет, `fetch` или `send`). В Chromium это поведение сквозные тесты не проверяют.
- В Firefox до версии 128 (ESR 115) content scripts не поддерживают `world: "MAIN"`. Там шим работает как обычный content script: подменяет `WebSocket` и `fetch` страницы через Xray (`window.wrappedJSObject`, `exportFunction`, `cloneInto`) и передаёт кадры мосту напрямую, без событий на `document`. В Firefox 128 и новее шим, как и в Chromium, работает в контексте страницы.
- В Firefox ESR 115 после отключения, удаления, перезагрузки или обновления расширения перезагрузите открытые вкладки. До этого `WebSocket` и `fetch` в них бросают `TypeError: can't access dead object` на любых сайтах, не только с NCALayer. Firefox уничтожает content script вместе с функциями, которые тот передал странице, и не даёт ему ничего сделать перед этим.

Linux, Firefox из snap и Flatpak:
- `nm install` находит Firefox по `~/.mozilla` или `~/.config/mozilla`. Профиль Firefox из snap лежит в `~/snap/firefox/`, и команда может его пропустить («пропущен»). Тогда создайте каталог `mkdir -p ~/.mozilla` и повторите `nm install`. Манифест ляжет в `~/.mozilla/native-messaging-hosts/`, откуда Firefox из snap версии 135 и новее читает его через xdg-desktop-portal.
- Firefox из Flatpak запускает хосты native messaging только через `xdg-native-messaging-proxy` в основной системе. OpenNCALayer его не ставит и права Flatpak не меняет, это настраивается вручную.
- Оба варианта не проверялись.

## Отличия и ограничения расширения

- Подкласс `WebSocket` страницы (`class X extends WebSocket`) для адреса NCALayer во всех браузерах создаёт обычный `WebSocket`, а не экземпляр `X`, потому что такой сокет создаёт расширение. В Firefox ESR 115 так происходит и для любого другого адреса: функцию, которую content script передал странице, Firefox вызывает с ней самой в `new.target`, и класс страницы до шима не доходит.
- В Firefox ESR 115 после отключения, удаления или обновления расширения открытые вкладки нужно перезагрузить, до этого `WebSocket` и `fetch` в них не работают.
- Chrome 109 (последний Chrome для Windows 7) заявлен минимальной версией, но не проверялся.
- Safari не поддерживается.
- Сокеты, которые сайт открывает из Web Worker, не перехватываются, для них по-прежнему нужны `wss` и CA.
- Одна вкладка держит через расширение не больше 256 открытых сокетов, все вкладки профиля вместе не больше 4096 (ограничение демона). Сокет сверх лимита сразу закрывается с кодом 1006, как при отказе в соединении.
- Пути native messaging для Yandex Browser и Opera не проверены. В Windows они читают ключ реестра Chrome, в Linux для Yandex Browser манифест пишется в `~/.config/yandex-browser/NativeMessagingHosts/`.
