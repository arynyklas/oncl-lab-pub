# Плагины в окне инструментов: подпись вручную

Страница «Плагины» окна «Инструменты» запускает операции установленных плагинов по вашему действию, без участия сайта. Вы выбираете файл или вводите текст, выбираете свой ключ, и программа показывает, для чего будет применён ключ. Плагин может применить ключ только после вашего подтверждения.

> Функция новая. Её проверяли тестами с настоящими модулями портов и синтетическими ключами RSA. Подпись через настоящее окно с настоящим ключом и службами НУЦ ещё не проверялась (подробности в разделе [«Чего страница не гарантирует»](#чего-страница-не-гарантирует)). Пока этого нет, не подписывайте здесь документы, от которых что-то зависит.

## Что это за страница

- Это раздел «Плагины» в боковом списке окна «Инструменты» (меню значка, пункт «Инструменты…»; рядом разделы «Обзор», «Подписать», «Проверка», «Продление», «Извлечение», «Метка времени», «Хеш», «Сведения»). Окно «Плагины…» из того же меню служит для установки и обновления плагинов.
- Страница показывает только операции, которые плагин объявил для этого окна в манифесте (`[[operations]]`, `manual = true`). Манифест описывает каждую операцию: какой запрос получит плагин, какие значения вводит пользователь, вид подписи (CMS, XML, «сырая» подпись) и нужную сеть. Запрос плагину строит программа по шаблону из манифеста. Плагин не выбирает операцию и не может подписать то, что вы не одобрили.
- Плагин без таких объявлений (сторонний или старой версии) работает для сайтов через WSS как обычно, а на странице значится с пометкой «нет операций для окна ручных инструментов». Плагин с объявлениями тоже работает через WSS как обычно, со своими диалогами и без билета. Объявленные операции касаются только этого окна, сервера и CLI.
- Страница не шифрует и не расшифровывает (шифрования в программе нет). Origin сайта она не подставляет: у такого вызова сайта нет.
- Ключ берётся из файла хранилища PKCS#12 или JKS с паролем. Токены и удостоверения на этой странице не предлагаются.

## Какие операции есть

Все они доступны только в этом окне (`manual = true`; `server = true` нет ни у одной, поэтому сервер и CLI их не получают), все применяют ключ и ходят в сеть только к серверам PKI (`tsp.pki.gov.kz`, `ocsp.pki.gov.kz`). Пояснения к списку:

- Колонка «Что делает» содержит название операции, которое выбрал автор плагина. Программа показывает его только в рамке «слова самого плагина, не проверены». Доверять следует строкам о виде подписи и странице подтверждения: их пишет программа по манифесту.
- Метод порта разбит на несколько операций, если плагин подписывает по-разному: с данными внутри или отсоединённо, с меткой времени или без. Это неизменяемый профиль операции, а не параметр формы: ядро подписывает именно так, и плагин отклониться не может. Все CMS-операции подписывают байты выбранного файла или введённого текста как есть, даже если файл сам является CMS: режим соподписи «автоматически», который передают порты, ядро заменяет на «никогда».
- Операция «Подписать элемент» XML требует атрибута `Id` у подписываемого элемента (так работает модуль подписи). Оба XPath абсолютные, вводятся текстом и показываются на странице подтверждения целиком, в кавычках. Пустой или не абсолютный XPath окно отклоняет до запуска плагина (`options-invalid`). У `efactoring.sign-xml-element` модуль сам отказывает до применения ключа, если родитель совпадает с элементом без учёта регистра; окна повтора в ручном окне нет, поэтому вызов кончается отказом `Denied` без подписи. Сравниваются строки: родитель `//data` при элементе `/r/data` совпадением не считается, и подпись окажется внутри подписанного элемента. Если XPath совпадает с несколькими узлами, подписывается первый в порядке документа. Префикс в XPath выбирает пространство имён: `SOAP-ENV` связан с пространством SOAP, любой другой префикс с пространством XMLDSig (так `/r/zz:data` выберет `<ds:data>`). Страница подтверждения показывает эти привязки в рамке плагина и говорит, какое значение элемент, а какое родитель.
- Профиль XML с расширенными параметрами может задавать преобразования подписываемой ссылки (`transforms`: первым `enveloped-signature`, затем не больше одной каноникализации; при подписи всего документа только `enveloped-signature`). Тогда на странице подтверждения и в окне установки есть строка «преобразования подписываемой ссылки: …». Если профиль преобразований не задаёт, их выбирает ядро.
- `qiwi`: модуль выбирает адреса алгоритмов по сертификату ключа, поэтому операций две, по одной на алгоритм (RSA-SHA256 и ГОСТ 2004). Ключ другого алгоритма даёт вызов, которого операция не объявляет, и окно отказывает до применения ключа (`options-mismatch`). Ключ ГОСТ 2015 не подписывает ни одной из них: модуль шлёт ему адреса ГОСТ 2004, подписывающий модуль их для такого ключа не принимает, и вызов кончается ошибкой без применения ключа. Ключи с сертификатами RSA-SHA1 тоже не подписывают: OpenNCALayer не делает подписей RSA-SHA1, и манифест не может объявить такой адрес алгоритма. Метод `logOut` не подписывает и не предлагается.
- «Сырая» подпись текста (`esf-osdkz.sign-plain-data`) подписывает UTF-8-байты введённого текста.
- Имена в колонке «Операция» стабильны. Их программа показывает в доверенной части страницы подтверждения.
- Версии портов с операциями опубликованы в индексе канала `beta` (`updates/v1/beta.json`), их можно поставить из каталога в окне «Плагины…». Пакет можно собрать и самим: `cargo xtask plugin pack plugins/<порт>`, затем «Установить из файла» (окно предупредит, что плагина нет в каталоге). Программа должна быть не старше версии из `min_core` манифеста.

### Каких операций нет и почему

Из 35 портов у 26 нет операций для этого окна. Каждый такой плагин окно показывает строкой «Плагин …, версия …: нет операций для окна ручных инструментов» с причиной, которую программа определяет по манифесту и реестру: в манифесте нет операций (плагин работает только для страниц); операции есть, но ни одной для этого окна; операциям нужны сетевые адреса, которых окно не выполняет; программа не приняла операции плагина. Почему непригоден конкретный метод порта, окно не говорит. Это описано ниже и в [инвентаризации портов](../design/manual-plugins-inventory.md): 166 методов 34 портов, из них 15 подходят, 59 не подходят, 92 не подписывают (порт `onaidocs` в инвентаризацию не входит).

Причины, по которым метод не может работать в этом окне. Число показывает, сколько из 59 непригодных методов затронуто причиной; у метода может быть несколько причин.

## Как проходит один вызов

1. Выбор операции. «Инструменты…», раздел «Плагины». Список сгруппирован по плагинам («Плагин <id>, версия <версия>», под ним «Операция <имя>»). Операция с пометкой «Использует ваш ключ; каждое применение требует вашего подтверждения» открывается кнопкой «Открыть». Операции, которые не используют ключ, окно не запускает. «Обновить список» перечитывает установленные плагины.
2. Форма. Для каждого параметра операции своё поле: «Документ <имя>: файл на ваш выбор, не больше <размер>» (путь к файлу), «Текст <имя> (не больше <N> символов)», выбор, переключатель или язык. Ниже поле «Хранилище ключей (PKCS#12, JKS)» с путём к файлу и кнопка «Продолжить». На этом шаге ничего не подписывается.
   - Файл читается в память один раз целиком. Программа считает его SHA-256 и дальше работает с этими байтами, а не с путём, так что подмена файла после этого шага ничего не меняет. Недоступный, пустой или слишком большой файл даёт ошибку формы.
   - Текст подписывается в том виде, как введён, без обрезки. Единственное изменение: переводы строк `\r\n` форма сводит к `\n` при снимке формы, и страница показывает и подписывает уже этот текст. Управляющие, невидимые и меняющие направление символы запрещены (на странице: «В тексте … есть символ, который нельзя показать как введён … Уберите его»), потому что подписываются байты, и страница должна показать их без подмены. Форма применяет то же правило, что и ядро. Из таких символов допустимы только перевод строки `\n` и табуляция.
3. Ключ. На странице «Ваш ключ» вы вводите пароль хранилища («Открыть хранилище») и видите список сертификатов. Сертификат с истёкшим или ещё не начавшимся сроком, а также не предназначенный для подписи, помечен и недоступен для выбора. Кнопка «Показать, что будет разрешено» готовит страницу подтверждения. При этом ключ открывается (проверяется пароль, сертификат сверяется с тем, что вам показали), но плагин не запускается и ничего не подписывается. Пароль очищается из поля сразу после отправки и хранится только для этой операции, не дольше 5 минут. После этого страница закрывается с сообщением «Страница ключа простояла слишком долго…», и пароль забывается. Когда операция заканчивается любым образом, пароль стирается из памяти. В журнал он не пишется.
4. Страница подтверждения. Только здесь вы разрешаете применить ключ. Заголовок «Подтвердите применение вашего ключа», под ним: «Всё на этой странице, кроме рамки, написала программа OpenNCALayer. Если вы подтвердите, ваш ключ подпишет один раз и только то, что здесь описано.» На странице:
   - Строки, которые пишет программа: «Операция: …»; «Плагин: <id>, версия <версия>»; вид подписи («подписывает вашим ключом: подпись CMS (PKCS#7) с расширенными параметрами» и т. п.); «Применений вашего ключа: 1. Подтверждение действует один раз и не запоминается.»; «вид подписи (задаёт ядро): …» (отсоединённая или с данными внутри, метка времени, весь документ или элемент и так далее); сеть («Сеть: только эти серверы национальной PKI: … Плагин может отправить им документ или данные, полученные из него.»); «SHA-256 файла пакета плагина» (для плагина не из пакета «SHA-256 манифеста и модуля плагина»).
   - Содержимое: «Файл, выбранный вами: <имя>»; «Размер», в том числе точное число байт; «SHA-256 файла». Для введённого текста показан точный текст в кавычках, переводы строк и табуляции обозначены явно. У операции над текстом строка «Файл, выбранный вами» остаётся с пустым именем, а размер и SHA-256 относятся к UTF-8-байтам текста. Если операция подписывает хеш документа, страница показывает хеш, посчитанный программой алгоритмом ключа.
   - Ключ, которым подпишут: имя в хранилище, серийный номер, владелец (CN), «Действителен до», SHA-256 сертификата.
   - Введённые вами значения, кроме файла, с пометкой «передаются плагину как есть». Если профиль читает XPath из введённого текста, он показан здесь.
   - Рамка «слова самого плагина, не проверены»: название плагина, название операции, выбранный вариант и XPath, которые задаёт сам плагин (XPath показаны целиком, до предела манифеста в 1024 байта). Эти слова не входят в то, что вы разрешаете, и не могут оказаться среди строк программы. Рамка отделена пояснением «В рамке ниже собственные слова плагина…».
   - Срок: «После подтверждения у плагина 120 с на применение ключа; затем разрешение истекает и подтвердить нужно заново.»
5. Подтверждение. Кнопка согласия одна, и она называет действие: «Подписать плагином <операция>»; рядом «Отмена: не подписывать». При открытии фокус стоит на «Отмена», Enter сам по себе не подтверждает, Escape отменяет. Кнопка начинает работать через 0,6 с после появления страницы («Кнопка заработает через мгновение после появления страницы»), чтобы в неё не попала серия кликов, предназначенных для другого. Страница, оставленная открытой на 5 минут, закрывается («Страница подтверждения простояла слишком долго и закрыта. Ничего не подписано, ключ не применялся.»). Подтверждение не сохраняется: следующий вызов потребует нового, и подтверждение одного вызова не подходит для другого.
6. Выполнение. «Плагин работает по вашему подтверждению. Ключ может применяться прямо сейчас.» На работу отводится 300 с с момента подтверждения. «Отмена» просит плагин остановиться. Если он не остановился за 10 с, страница сообщает об этом и разрешает уйти; плагин закончит в фоне, и неизвестно, применялся ли ключ.
7. Результат. Страница сообщает, что произошло с ключом: «Применение ключа: выполнено / не выполнялось / неизвестно». Зелёным «успехом» ничего не обозначается, потому что подпись в ответе плагина программа не проверяет. Если плагин вернул ответ и ключ применён один раз, страница показывает это нейтральным предупреждающим тоном: «Ключ применён; подпись не проверена» и «Подпись в ответе программа OpenNCALayer не проверяла.» Остальные исходы: «Ваш ключ БЫЛ применён, но плагин завершился некорректно», «Неизвестно, применялся ли ваш ключ … Считайте, что ключ мог быть применён», «Ничего не подписано: ваш ключ не применялся» с причиной и кодом.
   - Ответ плагина это его собственный текст. Он показан в рамке, очищен от управляющих символов, и на экране видны только первые 2 000 символов («… ещё N символов не показано»). Целиком ответ можно сохранить, если ключ подтверждённо применён, плагин завершился без отказа и ошибки и ответ есть. Тогда под ответом появляется кнопка «Сохранить ответ плагина (не проверен этой программой)». Она открывает окно сохранения и записывает весь ответ в точности как получен в один файл `.json`, без извлечения подписи, очистки и обрезки. Запись атомарная и никогда не заменяет существующий файл («Файл с таким именем уже есть и не был заменён»). Где жёсткие ссылки не поддерживаются (FAT, exFAT, часть сетевых папок), программа создаёт файл в исключительном режиме: существующий файл тоже не заменяется, а неполный файл при неудаче удаляется. При ошибке ввода-вывода страница показывает её причину. Ответ больше предела передачи плагина не сохраняется, страница называет его размер. Сохраняется ответ плагина, а не извлечённая подпись: у каждого порта своя форма ответа, и программа не знает, где в нём подпись. Эту подпись программа не проверяла. `PluginOutputBinding` для выбора места сохранения не используется.

### Предел размера документа

Окно читает документ целиком и держит его в памяти вместе с копиями модуля подписи, поэтому у него свой предел, заданный в `ManualLimits::desktop()`: 4 МиБ на 64-разрядной системе и 512 КиБ на 32-разрядной. Плагин держит весь документ в своей линейной памяти несколько раз (по измерениям до 12,1 байта на байт документа плюс 3 МиБ), а ядро резервирует под ключевой вызов 128 байт метаданных на байт документа. От размера документа зависит память всей программы, поэтому предел меньше 16 МиБ, которые допускает манифест. Бюджет проверяется до страницы подтверждения и до применения ключа. Документ или текст, для которых бюджета не хватает, отклоняются с кодом `resource-budget`; XML-операция без временного хранилища отклоняется с кодом `no-temporary-store`. Предел это размер, под который рассчитаны лимиты, а не жёсткая граница: проверка бюджета пропускает документы немного больше (при пределе 4 МиБ по измерениям примерно до 5,3 МиБ). Форма сужает объявленный в манифесте предел файла до предела окна (по умолчанию в манифестах 16 МиБ и 65 536 знаков на текст), чтобы отказ был виден до выбора файла.

## Чего страница не гарантирует

- Подпись в ответе плагина программа не проверяет. Ядро следит за тем, как применяется ваш ключ (что подписывается, с какими параметрами, сколько раз), но не разбирает и не проверяет подпись, которую плагин положил в ответ. Проверяйте результат отдельно (`oncl verify`, окно «Проверить»).
- Ответ плагина остаётся недоверенным текстом. Он никогда не попадает в заголовок или строки программы, показан в рамке, обрезан и очищен. Подтверждений в нём искать не нужно.
- Ключи ГОСТ. Алгоритм подписи для XML и CMS выбирает ядро по сертификату ключа. Поставляемые операции алгоритм не фиксируют, кроме двух операций `qiwi` (по одной на алгоритм ключа: RSA-SHA256 и ГОСТ 2004; другой ключ отклоняется до применения). Если описание операции или запрос плагина требует алгоритм, который не подходит ключу (например, адрес алгоритма RSA для ключа ГОСТ), ядро отказывает до применения ключа (`options-mismatch`, `unsupported-key`). Вызовы через окно проверяли синтетическими ключами RSA и, для `qiwi.sign-xml-gost2004`, ГОСТ 2004. Независимые проверки в тестах (OpenSSL, lxml) работают только с RSA; подпись ГОСТ 2004 проверена лишь верификатором самого репозитория (`oncl_xml::verify`).
- Метка времени. Тесты проверяют, что метка времени есть в CMS, но сам токен независимым инструментом не проверяют.
- Размер. Документ больше предела окна отклоняется до подтверждения (см. выше). Это защита памяти, а не оценка документа.
- Текст. Текстовые параметры не принимают управляющих, невидимых и меняющих направление символов (форма применяет то же правило, что и ядро; `\r\n` сводится к `\n`), потому что страница обязана показать подписываемые байты без подмены. Похожие по виду символы разных алфавитов, неразрывные и другие необычные пробелы, разные формы нормализации Юникода ядро принимает и не различает, а на странице они могут выглядеть как обычные. Сверяйте текст по SHA-256 и размеру, а не на глаз.
- Подтверждение становится разрешением только в обработчике кнопки страницы. Это обеспечено устройством кода, а не криптографией: в программе один вызов `after_user_confirmed`, нажатие кнопки передаётся как значение `PressToken`, остальные вызовы запрещены настройкой clippy, и тест сканирует дерево исходников. Враждебный код внутри самой программы мог бы подделать подтверждение. Целостность файла хранилища ключей остаётся границей доверия самой программы.
- Ключ открывается ещё до подтверждения, при подготовке страницы, поэтому пароль приходится вводить раньше, чем вы увидите, что будет подписано. Причина неудачного открытия не сохраняется: страница пишет одну фразу «Ключ не удалось открыть: проверьте пароль и хранилище».
- Окно не перепроверяет реестр в момент подтверждения. Страница подтверждения может быть открыта до 5 минут, и плагин, удалённый за это время, может выполниться один раз. Подменить его нельзя: разрешение привязано к хешу пакета.
- Казахский текст страницы составлен по словарю других окон программы; носитель языка его по экранам не вычитывал.
- Доступность. В проверке на настоящем окне с синтетическим плагином фокус стоял на «Отмена» при масштабе 100 % (английский, русский и казахский тексты). При 200 % и с экранным диктором проверки не было.
- Журнал. Постоянного журнала документов окно не ведёт. События применения ключа и отказов уходят в журнал `tracing` с целью `oncl::plugin_audit`, без байтов документа, параметров и паролей.

## Отказы: как читать код на странице

Если плагин отклонён до применения ключа, страница пишет причину словами и код. После неудачной подготовки код стоит в скобках («Ключ не удалось открыть: проверьте пароль и хранилище. (key-unavailable)»), после запуска выводятся строки «Код: <код>» и «Причина: …». Тот же код видят сервер, CLI и журнал аудита. Плагин кода не видит, для него это просто `PermissionDenied`. При любом отказе из списка ключ не применяется, кроме `key-use-spent`: это повторное применение, а первое остаётся выполненным.

`ErrorCode` это публичный код ошибки, он не меняется; `subcode` рядом с ним стабильно обозначает причину. Подкоды не переиспользуются и не перенумеровываются. | `audit-fact-too-long` | `PermissionDenied` | прочее | версия плагина или имя гранта длиннее 255 байт, в журнал не записать: применение не начинается | общий текст и код |
| `content-binding-unavailable` | `PermissionDenied` | прочее | CLI не может заранее вычислить ожидаемое содержимое (форма «хеш»), грант не выдаётся | общий текст и код |
| `resource-budget` | `MemoryLimit` | подготовка (до ключа) | документ или текст не умещаются в бюджет памяти окна (для слишком большого документа `ErrorCode` равен `InputLimit`) | да |
| `no-temporary-store` | `MissingTemporaryStore` | подготовка (до ключа) | операция подписывает XML, а у движка нет временного хранилища | да |

Код, которого нет в таблице, пришёл из более поздней версии. Считайте его обычным отказом с кодом `ErrorCode`.

## Установка и обновление плагина с операциями

Если у плагина есть операции, окно «Установка плагина» (или «Обновление плагина») при установке из каталога или из файла показывает отдельный блок: «Плагин предлагает в окне ручных инструментов такие действия (каждое описывает программа)». Для каждой операции там есть:

- «Действие <имя>» и строки программы: «подписывает вашим ключом: …» (вид подписи) или «не использует ваш ключ»; «вид подписи (задаёт ядро): …» со всеми отличиями профиля от стандартного (отсоединённая или с данными внутри, метка времени, весь документ или элемент, перевод строк, результат DER, PEM или base64); сеть («без сети» или «сеть: только PKI-серверы ядра»); «только ручное окно (не для серверов и CLI)» или «доступно также серверам и CLI»;
- рамка «Плагин называет его так (слова самого плагина, не проверены)» с названием операции и XPath, которые задал плагин;
- в списке «Плагин сможет» строка о том, что плагин будет предлагать в окне ручных инструментов действия, которые могут использовать ваш ключ, сеть или больше возможностей ядра.

При обновлении добавляются строки «НОВОЕ или ШИРЕ: …»: новая или изменённая операция, новое применение ключа или другой вид подписи, больше функций ядра, более широкая сеть, доступ для серверов и CLI. Обновление из каталога, которое добавляет или расширяет такую операцию, само не ставится. Оно ждёт, пока вы нажмёте «Обновить» в окне «Плагины…», а до тех пор работает прежняя версия. Без запроса ставится только обновление, которое ничего не добавляет и не расширяет. Кнопка «Установить» или «Обновить» начинает работать через 1,5 с. Название плагина в этом окне тоже пишет сам плагин; доверяйте блоку операций, который пишет программа.

## Для оператора: сервер и CLI

Операцию плагина можно выдать серверу (`[[plugins.permissions]]`, `plugin_bytes = true`) и CLI (`oncl plugin call --plugin-bytes`), только если она объявляет `server = true`. Ни одна из 30 поставляемых операций этого не объявляет, поэтому выдавать серверу и CLI по ним нечего: сервер пропускает такой грант с ошибкой в журнале, CLI отказывает с кодом `not-declared`. Плагины без объявлений работают с сервером и CLI по меткам оператора, как прежде. Подробности, поля аудита и замечание об откате журнала в [server.md](server.md#плагины) и [cli.md](cli.md#плагины-oncl-plugin).
