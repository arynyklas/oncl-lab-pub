# oncl-core

Встраиваемый Rust SDK проекта [OpenNCALayer](https://github.com/arynyklas/OpenNCALayer):
типизированные потоковые операции подписи, проверки, валидации, инспекции и меток времени над
файлами и потоками байт. Доверие, ключи, часы, сеть, аудит и лимиты ресурсов задаёт приложение,
в которое встроен SDK. У SDK нет интерфейса, демона, слушающего порта, установщика и
самообновления, графическая сессия ему не нужна.

Версия до 1.0 (`0.1.0-alpha.*`). Между альфа-версиями возможны несовместимые изменения, они
перечислены в заметках о миграции в [`docs/dev/sdk.md`](../../docs/dev/sdk.md). Крейты в
crates.io не публикуются, поэтому подключайте их по git с тегом выпуска или по path (ниже);
`cargo add` с версией из реестра не сработает.

## Подключение

По git, с тегом выпуска (`Cargo.lock` закрепит его коммит):

```toml
[dependencies]
oncl-core = { git = "https://github.com/arynyklas/OpenNCALayer", tag = "v0.1.3", features = ["full"] }
oncl-pki = { git = "https://github.com/arynyklas/OpenNCALayer", tag = "v0.1.3" }
```

или по path, из рабочей копии репозитория на проверенном вами теге:

```toml
[dependencies]
oncl-core = { path = "OpenNCALayer/crates/oncl-core", features = ["full"] }
oncl-pki = { path = "OpenNCALayer/crates/oncl-pki" }
```

Минимальный SDK (`default-features = false`, то же, что по умолчанию) включает CMS/CAdES,
хеширование, PKI-валидацию, ключи PKCS#12 и JKS из файлов и из памяти, ключи, названные
приложением, пакеты операций и инспекцию. Дополнительные features:

| feature   | добавляет                                                                  |
|-----------|----------------------------------------------------------------------------|
| `tokens`  | аппаратные токены и удостоверения личности как источники ключей (`oncl-token`) |
| `xml`     | подпись, добавление подписи и проверка XMLDSig / XAdES / WS-Security (`oncl-xml`) |
| `pdf`     | подпись и проверка PAdES (`oncl-pdf`)                                      |
| `jose`    | создание, добавление и проверка JWS / JWT                                  |
| `plugins` | безголовый хост плагинов WebAssembly (включает `xml`)                      |
| `full`    | всё перечисленное; интерфейса, desktop, механизма обновления, сервера и асинхронного рантайма нет и здесь |

## Примеры

Примеры запускаются командой `cargo run -p oncl-core --example <имя>`. Каждый выпускает
одноразовую RSA PKI при запуске и не обращается к сети:

- `sign_file [КАТАЛОГ [ФАЙЛ]]` создаёт отсоединённую подпись CMS файла ключом PKCS#12 при строгой
  валидации. Применение ключа записывает аудит приложения (`KeyUseGuard`).
- `verify_file КАТАЛОГ ФАЙЛ` проверяет эту подпись и завершается ненулевым кодом, если вердикт не `Valid`.
- `custom_transport` подключает к валидации собственный `HttpTransport` приложения. Без сети
  строгая подпись отклоняется до применения закрытого ключа.

Пример `sdk_probe` сверяет результаты с независимыми инструментами проверки и служит приёмочной
пробой, а не руководством по встраиванию.

## Контракт на одной странице

- `Engine` строится из `EngineServices` (службы приложения), операция начинается вызовом
  `Engine::begin(ExecutionGrant, OperationPolicy, control)`. Права выдаёт доверенный код
  приложения, сетевой запрос их выдать не может.
- Закрытый ключ применяется через `KeyUseGuard`: `before_use` должен надёжно записать
  применение до того, как ключ будет применён, а его отказ запрещает применение. Ошибки несут
  `AppliedState` (`NotApplied`, `Applied`, `Unknown`). SDK не обещает ни отката, ни ровно одного
  применения.
- Отчёты (`Verdict`) отдельно сообщают о целостности подписи, цепочке до якоря, сроке действия,
  отзыве, доказательстве метки времени и заявленном времени. Если доказательств нет, подпись не
  считается действительной.
- По умолчанию на операцию приходится 1 ГиБ байт документа и 1 ГиБ учтённых живых буферов;
  документ больше 1 ГиБ отклоняется. Это лимиты учёта, а не измерение RSS. Полный список лимитов,
  правила semver, стабильность ошибок и готовность к публикации описаны в
  [`docs/dev/sdk.md`](../../docs/dev/sdk.md).
