# Журнал изменений

Здесь записано то, что видит пользователь. Новые записи добавляются в раздел «Unreleased», а при выпуске версии переносятся в её раздел. Выпущенные разделы не меняются.

## Unreleased

### Добавлено

- Каталог плагинов читает плагины сторонних издателей: предлагает и ставит их, обновляет и отзывает по правилам издателя и OpenNCALayer. Разрешения из записи каталога сверяются с пакетом, пакет с другими разрешениями не ставится. Если издателя отключили в каталоге, его плагины выключаются с уведомлением. Пока установлен плагин издателя, каталог проверяется раз в 1–3 часа.
- Плагин стороннего издателя может заменить порт проекта: OpenNCALayer предлагает замену в окне «Замена порта» с издателем, возможностями нового плагина и ссылкой на его исходный код. «Заменить» ставит плагин издателя вместо порта, удаляет порт с его настройками и сообщает «Порт заменён»; если каталог к этому моменту замену уже не предлагает или обновления выключены, ничего не меняется. «Не сейчас» оставляет порт без обновлений из каталога (отзывы действуют), окно больше само не открывается, а в окне «Плагины» у порта появляются строка «Доступна замена от издателя …» и кнопка «Заменить…». При выключенных обновлениях замена не предлагается; если издатель больше не активен, порт снова обычный. В `publishers.json` один плагин может заменять только один порт.
- На сайте проекта появился раздел «Издатели»: каждый издатель с префиксом идентификаторов, сайтом и состоянием (издатель на покое помечен «не выпускает новых версий», отключённый — датой отключения, его плагины со страниц убраны). На странице издателя — его плагины и все версии с каналом, ссылками на копию пакета, архив исходного кода, `BUILDINFO.json` и выпуск в Releases проекта, командой для проверки сборки и пометкой, что код OpenNCALayer не проверял. В каталоге плагинов появилась таблица «Плагины издателей», а страница порта называет плагин издателя, который его заменяет.
- Библиотека для Rust: `TufClient::verify_cached_top_level` и `TufClient::verify_cached_current_role` (сохранённая роль только в версии, которую перечисляет сохранённый снимок), `CatalogBuilder::delegations_unavailable` и `PublisherPolicy::TARGET` в `oncl-update`, цели и роли издателей в `tuf::testing::Repo`, `PluginModules::builtin_modules` и `Store::replace` в `oncl-plugin`.
- Настройка «Проверять отзывы плагинов» в окне «Настройки…» → «Обновления» (`updates.check_revocations` в `settings.json`, по умолчанию включена). При выключенных обновлениях она решает, проверяет ли OpenNCALayer каталог плагинов по расписанию; если снять и её, программа по расписанию к каталогу не обращается, а отзывы применяются только по кнопкам «Проверить сейчас» и «Обновить каталог» и к каталогу, скачанному по просьбе сайта. В `docs/user/updates.md` добавлен раздел «Сетевые запросы».
- Эталонный сборщик плагинов сторонних издателей: программа `oncl-pack` и образ `oncl-plugin-builder` с ней (`xtask/assets/plugin-builder/Dockerfile`; в ghcr.io его публикует workflow `plugin-builder.yml`, запускаемый вручную). `oncl-pack` делает канонический архив исходников (`.src.tar.gz`) из каталога или ревизии git, собирает из него пакет `.onclp` без сети дважды и сравнивает сборки, а также пересобирает опубликованный пакет и сверяет его sha256. Допустимые образы перечисляются в `publishers/builders.toml`. Как собирать, описано в `docs/dev/publishers.md`.
- Инструменты сторонних издателей плагинов `cargo xtask vendor`: ключ издателя (`keygen`), файл подключения (`onboard`, `check-onboarding`), архив исходников (`source`), сборка в эталонном образе (`build`), черновик и подпись версии роли (`add`, `set`, `prune`, `sign`, `cosign`), проверка выпуска (`check`, `verify`). Для CI — проверки PR выпуска с ответом в JSON (`check-pr`, `rebuild`, `provenance`, `verdict`) и `.src.diff` (`src-diff`). В `publisher.toml` появилось необязательное `binary_files`. Пошаговое описание — в `docs/dev/publishers.md`.
- Плагины издателей: лицензия и лицензии зависимостей из списка OSI без устаревших идентификаторов и `LicenseRef-`; `THIRD-PARTY.txt` копии выпуска содержит полные тексты лицензий зависимостей; `min_core` выпуска не ниже 0.1.3; `cargo xtask tuf check` предупреждает (`publisher-rules`) о последних ролях, нарушающих сегодняшние правила. Проверка git-ревизии издателя идёт в отдельном контейнере.
- Выпуски сторонних издателей принимает бот: workflow `publisher-pr.yml` проверяет PR с новой версией роли издателя, пересобирает каждый новый пакет из архива исходников в эталонном сборщике, копирует пересборку, архив, `.src.diff`, `THIRD-PARTY.txt` и `BUILDINFO.json` в неизменяемый выпуск `pub-<издатель>-<sha256>` этого репозитория, затем сливает PR и публикует Pages. PR подключения издателя открывается по шаблону `.github/PULL_REQUEST_TEMPLATE/publisher.md`, его проверяет `vendor check-onboarding` в CI. Как это настроить владельцу, описано в `docs/dev/release.md`, раздел 1.

### Изменено

- При выключенных обновлениях и включённой настройке «Проверять отзывы плагинов» OpenNCALayer всё равно проверяет каталог плагинов по расписанию и выключает отозванные плагины, но ничего не ставит и не обновляет. «Проверить сейчас» при выключенных обновлениях делает то же.
- Плагин из каталога ставится после согласия пользователя, только если каталог всё ещё предлагает ту же версию: если её отозвали, пока было открыто окно установки, ничего не ставится. При запуске OpenNCALayer удаляет пакеты и настройки плагинов, которых уже нет среди установленных и которые не менялись дольше 10 минут (их мог оставить сбой).
- Библиотека для Rust (`oncl-plugin`, feature `distribution`): несовместимо изменился публичный API. `Store::install` принимает издателя плагина, хранилище запоминает издателя установленного плагина, хранит `publishers.json` и роли издателей; `oncl-update` получил `choose_installed`. Что поменять в своём коде, описано в `docs/dev/sdk.md`, «Переход с 0.1.1 на 0.1.2».

## 0.1.2-beta.1 — 2026-11-18

### Изменено

- Автообновление продолжает работать, когда в метаданных обновлений появятся записи сторонних издателей плагинов. Версии 0.1.0 и 0.1.1 такие метаданные не принимают: чтобы и дальше получать обновления, установите 0.1.2 или новее.
- Библиотека для Rust (`oncl-update`): клиент TUF по умолчанию читает метаданные так же, как программа с 0.1.2, и не перестаёт обновляться, когда в них появятся записи издателей. Прежнее поведение 0.1.0 и 0.1.1 включается явно (`Profile::Legacy`).
- Библиотеке для Rust больше не нужен раздел `[patch.crates-io]`: `streebog` и `hmac` берутся прямо из crates.io. Хеширование секретов при согласовании и обёртке ключей ГОСТ теперь выполняет сам `oncl-gost`, с прежней очисткой памяти.
- Библиотека для Rust (`oncl-update`): несовместимо изменился публичный API, добавлены каталог плагинов сторонних издателей и делегированные роли TUF. Что поменять в своём коде, описано в `docs/dev/sdk.md`, «Переход с 0.1.1 на 0.1.2».

## 0.1.0

Первый стабильный выпуск.

### Добавлено

- Подпись и вход по ключам из файлов `.p12`, `.pfx`, `.jks`; проверка сертификатов НУЦ.
- Перенесённые из оригинала плагины сторонних сайтов; каталог плагинов и установка из файла.
- Расширение браузера и сертификат для браузера (TLS) как два способа подключить сайт.
- Установщики для Windows (в том числе Windows 7), macOS и Linux (AppImage); пакет `openncalayer-bin` для Arch Linux.
- Автоматическое обновление установленной копии с проверкой подписи индекса (minisign и TUF).
- Командная строка `oncl` и HTTP-сервис `oncl-server`; библиотека для Rust.
- Документы до 1 ГиБ по умолчанию.
- Токены и удостоверение личности (экспериментально, выключены по умолчанию).
